Password strength test

Type a password to see the guess count behind it, which patterns an attacker would exploit first, and roughly how long it would survive. It is read from the field locally and never sent anywhere.

Use a password you are considering, not one in active use, if others can see your screen.

This is the only action on the site that uses the network. It uses k-anonymity: your browser hashes the password with SHA-1 and sends only the first five characters of that hash. The service never receives the password or the full hash, and the result is not stored.

How the estimate works

The score is deliberately conservative. It starts from the number of possible characters raised to the length, then applies heavy penalties for anything an attacker would try early: a well-known password, keyboard runs like qwer, repeated characters, or a year.

Length beats complexity. “Offline attack” assumes an attacker has stolen a password database and can test 10 billion guesses per second. “Online attack” assumes 1,000 guesses per second against a login form that limits attempts.

What actually helps

  • Use a password manager. Then every site gets a unique random password and you memorise one strong one.
  • Prefer length. Four random words beat eight clever characters.
  • Turn on two-factor authentication. A stolen password is far less useful with it.
  • Never reuse. One breach should not open your other accounts.

Privacy

Your password is processed by code in this page. There is no server, no logging and no analytics. The optional breach check sends only a five-character hash prefix, and only when you click the button.
