About, method and limits

BrowserGuard is a SIWES mini project: a set of practical security tools, plus the Chromium extension they share code with. This page explains how the tools work and what they cannot tell you.

The project

BrowserGuard was developed in 2026 as a Students Industrial Work Experience Scheme (SIWES) mini project by Ayomide Jesse. It has two parts that share one idea: make browser-level security checks explainable rather than opaque.

  • The site — four tools you run deliberately, one input at a time.
  • The extension — the same analysis, applied automatically while you browse.

The URL-analysis engine is a single implementation in src/security/. The copy used by this site is generated from it, so a rule fixed in one place is fixed in both. Source: github.com/Jessedrt/BrowserGuard.

How the link checker decides

Each trait adds a weighted number of points, and the total is capped at 99:

45 pointsLookalike brand domain, misleading user-info section
35–30 pointsIP address host, many subdomains, punycode
20 pointsLong domain, odd encoding, HTTP login page
15–10 pointsLink shortener, unusually complex path

The bands are: 0 no indicators, 1–29 low risk, 30–59 suspicious, 60+ high risk. The score is a weighted tally, not a probability — “40/99” does not mean a 40% chance that a site is fraudulent.

What these tools cannot do

They cannot prove a site is safe

A clean result means no configured structural signal matched. Phishing pages on ordinary-looking domains pass these checks, which is why the wording is “no known indicators”, never “safe”.

They do not open or contact the link

There is no server component, so nothing is fetched, no DNS lookup is performed, and no certificate is inspected. A page cannot be judged by its content here.

The password score is a model, not a measurement

It estimates the guesses an attacker would need, penalising known passwords and predictable patterns. It cannot know whether a specific password has been reused elsewhere, and it does not know a target site's actual rate limiting.

The privacy check reports what this browser exposes

It is a demonstration of available signals, not a complete fingerprinting test and not a score you can “pass”. Blocking more signals can make a browser rarer and therefore easier to single out.

None of this replaces antivirus or professional advice

Browser-level checks cover what a browser can see. They do not scan a device, detect installed malware, or respond to an active incident.

Privacy statement

  • No accounts, cookies, analytics or third-party fonts.
  • Link and password checks are processed in the page and never transmitted.
  • The one optional network request — the breach check — uses k-anonymity: a five-character SHA-1 prefix and nothing else.
  • Nothing is written to local storage or the URL, apart from a link you paste into the checker yourself.

Project facts

Design notes

Blue signals protection, green an absence of indicators, amber suspicion and red high risk. Those colours are used consistently across the site and the extension, and they are never used decoratively.
